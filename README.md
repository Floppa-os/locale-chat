# locale-chat
Конфигурация мессенджера находится в файле **`config.py`** в корне проекта.


### Что там хранится

В этом файле задаются ключевые параметры работы системы:

1. **Настройки сервера**  
   * `SERVER_HOST` — IP‑адрес, на котором запускается сервер (например, `'0.0.0.0'` для приёма подключений со всех интерфейсов).  
   * `SERVER_PORT` — порт сервера (по умолчанию `8888`).

2. **Настройки клиента**  
   * `CLIENT_HOST` — локальный IP‑адрес клиента (например, `'127.0.0.1'`).  
   * `CLIENT_PORT` — локальный порт клиента (по умолчанию `8889`).

3. **Пути и лимиты**  
   * `DOWNLOAD_DIR` — папка для сохранения принятых файлов (например, `'./downloads'`).  
   * `MAX_FILE_SIZE` — максимальный размер передаваемого файла в байтах (по умолчанию `10 * 1024 * 1024`, т. е. 10 МБ).

### Как использовать

1. Откройте файл `config.py` в корне проекта.  
2. Измените значения переменных под свои нужды (например, поменяйте порты или путь к папке загрузки).


### Почему именно так

* **Централизация.** Все настройки в одном месте — легко менять и документировать.  
* **Разделение окружения.** Отдельные параметры для сервера и клиента позволяют запускать их на разных машинах или портах.  
* **Гибкость.** Пути и лимиты можно адаптировать под конкретную инфраструктуру.

> **Примечание:** Если вы публикуете проект на GitHub, убедитесь, что в `config.py` нет ваших личных данных и других штук (паролей, логинов, ключей, шлёпиков)

# Инструкция по работе с проектом локального мессенджера
### Общая структура проекта

Проект разбит на **3 основные папки** и несколько ключевых файлов:


1. **`client/`** — клиентская часть (запускается у каждого пользователя).  
2. **`server/`** — серверная часть (работает как центральный узел).  
3. **`shared/`** — общие модули (используются и клиентом, и сервером).  
4. **`config.py`** — глобальные настройки.  
5. **`requirements.txt`** — список зависимостей.  
6. **`README.md`** — эта документация.

---

### Подробное описание файлов

#### 1. `config.py`
**Что хранит**: глобальные параметры сети и поведения.  
**Ключевые настройки**:
- `SERVER_HOST`, `SERVER_PORT` — адрес и порт сервера.
- `CLIENT_HOST`, `CLIENT_PORT` — адрес и порт клиента (обычно не используется).
- `DOWNLOAD_DIR` — папка для сохранения принятых файлов.
- `MAX_FILE_SIZE` — максимальный размер файла для отправки (в байтах).

**Как менять**: редактируйте значения под свою сеть (например, измените `SERVER_HOST` на IP вашего сервера).

#### 2. `shared/protocol.py`
**Что хранит**: формат сообщений и алгоритм их упаковки/распаковки.  
**Основные функции**:
- `create_message()` — формирует JSON-сообщение с текстом и метаданными.
- `create_file_chunk()` — разбивает файл на части для передачи.
- `parse_message()` — распаковывает байтовые данные в словарь.


**Как менять**:  
- Чтобы добавить новые поля в сообщение (например, аватар), измените словарь в `create_message()`.
- Для смены формата передачи файлов — перепишите `create_file_chunk()`.

#### 3. `shared/utils.py`
**Что хранит**: вспомогательные алгоритмы.  
**Основные функции**:
- `get_file_hash()` — вычисляет MD5-хеш файла (для проверки целостности).
- `split_file()` — делит файл на чанки заданного размера.


**Как менять**:  
- Чтобы использовать другой алгоритм хеширования (например, SHA-256), замените `hashlib.md5()` на `hashlib.sha256()`.
- Чтобы изменить размер чанка, передайте другой `chunk_size` в `split_file()`.

#### 4. `server/server.py`
**Что хранит**: логику работы сервера.  
**Ключевые компоненты**:
- `MessengerServer` — класс, управляющий подключениями.
- `clients` — словарь подключённых пользователей (`{адрес: имя}`).
- `messages` — список всех сообщений (в памяти).
- `files` — временные данные переданных файлов.

**Как менять**:  
- Чтобы сохранять сообщения в базу данных, замените список `messages` на запись в файл/БД.
- Для ограничения числа подключений — добавьте проверку в `start()`.

- Чтобы логировать действия, вставьте `print()` или запись в файл в методах `handle_client()` и `broadcast()`.


#### 5. `client/network.py`
**Что хранит**: код для сетевого взаимодействия клиента.  
**Ключевые классы**:
- `ClientNetwork` — отвечает за подключение к серверу и обмен данными.


**Как менять**:  
- Чтобы добавить шифрование, оберните `send()` и `recv()` в функции шифрования.
- Для поддержки повторных подключений — реализуйте механизм реконанекта в `connect()`.


#### 6. `client/ui.py`
**Что хранит**: консольный интерфейс пользователя.  
**Ключевые элементы**:
- `ConsoleUI` — класс, отображающий сообщения и принимающий ввод.


**Как менять**:  
- Чтобы сделать графический интерфейс, замените `input()` и `print()` на Tkinter/PyQt.
- Для поддержки команд (например, `/help`) — добавьте обработчик в цикл `run()`.

#### 7. `client/main.py`
**Что хранит**: точку входа для запуска клиента.  
**Как менять**:  
- Чтобы добавить авторизацию, вставьте запрос пароля перед `ui.run()`.
- Для сохранения настроек пользователя — создайте файл конфигурации.

---

### Как вносить изменения

1. **Измените `config.py`** под свою сеть (IP, порты, папки).  
2. **Обновите протокол** в `shared/protocol.py`, если нужно добавить новые типы сообщений.  
3. **Доработайте сервер** в `server/server.py` для сохранения данных или ограничения доступа.  
4. **Модифицируйте клиентский интерфейс** в `client/ui.py` под свои нужды.  
5. **Проверьте зависимости** в `requirements.txt` и установите их:  
   ```bash
   pip install -r requirements.txt
   ```
6. **Запустите сервер**, затем клиентов:  
   ```bash
   # Сервер
   python server/server.py

   # Клиент (укажите имя)
   python client/main.py Иван
   ```

---

### Рекомендации по расширению

- **Для хранения сообщений**: добавьте SQLite или Redis в `server/server.py`.  
- **Для безопасности**: внедрите SSL/TLS в `client/network.py` и `server/server.py`.  
- **Для GUI**: замените `client/ui.py` на код с использованием Tkinter или PyQt.  
- **Для масштабирования**: перепишите сервер на асинхронный фреймворк (например, `asyncio`).

---

### Важные замечания

- Все сообщения передаются в **JSON-формате** (см. `shared/protocol.py`).  
- Файлы разбиваются на **чанки** (по умолчанию 1 МБ) для устойчивости к разрывам соединения.  
- Сервер хранит сообщения **в оперативной памяти** — при перезапуске они удаляются.  
- Клиент сохраняет принятые файлы в папку, указанную в `DOWNLOAD_DIR`.
